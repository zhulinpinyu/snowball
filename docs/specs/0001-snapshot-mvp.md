# Spec 0001 — Snowball 家庭资产快照（MVP）

Label: ready-for-agent

## Problem Statement

投资分散在支付宝、微信、雪球等多个 App 里，家庭成员（多人）各持有若干基金、股票。没有一个统一的地方能看到：家里总共攒下多少资产、每个人/每个平台/每类资产的占比如何、整体趋势是涨是跌。各 App 的收益口径不一，且存在定投，本金持续变化，仅凭单 App 数字无法汇总。

## Solution

一个手机优先的网页应用（可在微信内置浏览器打开）：用户每隔一段时间（不固定日期）创建一张「快照」，逐条录入每个持仓的市值与累计收益（均从所属 App 抄录），并带上所属人、平台、资产类型、标的代码标签。应用据此展示家庭总资产趋势曲线与按人/平台/资产类型的占比，可下钻查看单个标的的历史走势。数据存于浏览器 localStorage，支持导出/导入 JSON 以便备份与未来迁移。

术语以 `CONTEXT.md` 领域词汇表为准（快照、持仓记录、标的、所属人、平台、资产类型、累计收益）。

## User Stories

1. As a 家庭成员, I want 新建一张快照并标注日期, so that 这一期的所有持仓记录都挂在同一个时间点上，不会错位。
2. As a 家庭成员, I want 在一张快照里逐条添加持仓（标的名称、代码、资产类型、所属人、平台、市值、累计收益）, so that 我能按 App 里的数字如实抄录。
3. As a 家庭成员, I want 录入时从已有的所属人/平台/资产类型中选择而非重复输入, so that 录入更快且标签口径一致。
4. As a 家庭成员, I want 通过基金/股票代码识别同一标的, so that 同一只基金在两个平台持有时仍能按标的汇总。
5. As a 家庭成员, I want 查看家庭总资产随时间的趋势曲线, so that 我能看到财富整体的涨跌走向。
6. As a 家庭成员, I want 查看按所属人的资产占比, so that 我知道家里每个人的资产份额。
7. As a 家庭成员, I want 查看按平台的资产占比, so that 我知道钱都分散在哪些 App 里。
8. As a 家庭成员, I want 查看按资产类型的占比, so that 我知道基金、股票各占多少。
9. As a 家庭成员, I want 点击占比图的某个分块后看到该维度的明细持仓, so that 我能知道占比背后具体是哪些标的。
10. As a 家庭成员, I want 查看某个标的跨快照的市值与累计收益走势, so that 我能看到这只基金/股票一直是在赚还是在亏。
11. As a 家庭成员, I want 在快照列表里看到每期家庭总资产与较上期的涨跌, so that 我不用点进去也能扫一眼变化。
12. As a 家庭成员, I want 事后编辑或删除某条持仓记录乃至整张快照, so that 抄错、漏抄时可以修正。
13. As a 家庭成员, I want 添加新的所属人/平台/资产类型, so that 家庭成员和渠道变化时无需改代码。
14. As a 家庭成员, I want 将全部数据导出为 JSON 文件, so that 我能备份或换手机时迁移。
15. As a 家庭成员, I want 导入之前导出的 JSON, so that 数据丢失或换设备后可恢复。
16. As a 家庭成员, I want 在微信内置浏览器里正常使用, so that 我能随手打开记录。
17. As a 使用电脑的家庭成员, I want 宽屏下页面自动分栏, so that 我偶尔在电脑上看也不难受。
18. As a 家庭成员, I want 收益为正/为负用不同颜色和正负号区分, so that 赚亏一眼可辨。

## Implementation Decisions

- 技术栈：Vite + React + shadcn/ui + Tailwind CSS；用 shadcn 官方 vite 模板初始化。
- 图表使用 shadcn 的 Chart（Recharts 封装）：折线图（总资产趋势、标的走势）+ 饼图（占比）。不引入 ECharts。
- 数据模型（领域核心，来自讨论定稿）：
  - 快照：{ id, 日期 }；持仓记录：{ id, 快照id, 标的名称, 标的代码, 资产类型, 所属人, 平台, 市值, 累计收益 }。
  - 所属人/平台/资产类型是简单的可增删标签实体，非枚举硬编码。
  - 不记录本金/投入流水；收益率由 (累计收益)/(市值−累计收益) 反推，仅在展示层计算。
- 持久化：localStorage 单键存储全部数据；提供导出/导入 JSON（导入为整体覆盖）。
- 领域核心为纯函数模块「快照库」：接收全部数据，返回增删改结果与聚合结果（趋势、占比、标的走势）。持久化与 UI 均依赖此模块，UI 组件不做单元测试。
- 交互流程：主入口为「新建快照 → 在快照内逐条加持仓」；不提供随手单条游离记录。
- 收益口径：累计收益为各 App 抄录数字，可能因部分赎回出现跳变/清零，不做修正，允许备注。
- 遵循 ADR 0001：快照式手工记录，不自动拉取净值（见 docs/adr/0001）。
- 手机优先、响应式布局；宽屏自动分栏，不单独做 PC 版。
- 历史快照允许自由增删改，无审计。

## Testing Decisions

- 好的测试只测外部行为：对「快照库」纯函数模块给定输入数据，断言聚合/增删改输出，不测内部实现。
- 测试模块：快照库（CRUD、总资产趋势序列生成、各维度占比计算、标的走势提取、收益率反推、导入/导出数据的序列化往返）。
- 无既有先例（新项目）；测试框架 Vitest，与 Vite 生态一致。
- UI 层不单测（缝隙之上的部分）。

## Out of Scope

- 自动拉取基金净值/股票行情（基金代码仅作唯一标识）。
- 定投流水、买卖交易记录、本金台账。
- 多用户/账号体系、家人间的数据云同步。
- 收益清零跳变的修正或"已落袋收益"追踪。
- 桌面专版、离线 PWA、微信授权登录。
- 存款/黄金等类型的数据结构支持已在设计中保留，但本期不做专属录入入口。

## Further Notes

- 产品显示名可另行确定（候选：「家庭资产账本」），仓库名已定为 snowball。
- 部署形态：纯静态文件，可托管到任意静态服务器后在微信中打开。
