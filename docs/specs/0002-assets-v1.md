# Spec 0002 — Snowball v1：家庭资产（持仓 × 现价 + 现金账户）

> 取代 Spec 0001（快照抄录 MVP）。术语以 CONTEXT.md 为准，模型与行情决策见 ADR 0002、ADR 0003。

## Problem Statement

家庭的钱分散在多个 App 与银行：基金（支付宝/天天基金）、股票（雪球/券商）、存款与现金等价物（活期/定期/余额宝/零钱）。
旧 MVP 按"整期快照抄市值 + 累计收益"设计：要求整期对齐、每期抄两个数，且 App"累计收益"口径掩盖真实资产。
v1 目标：随时打开就看到家庭**当前的真实资产**（按最新行情），录入只发生在变化时（份额/成本价/余额），价格由行情接口自动取得。

## Scope（v1）

- 资产类型：A股场外基金、A股股票/场内、现金账户（活期/定期/货币基金/零钱）。
- 单人单设备本地使用：localStorage 持久化 + JSON 导出/导入备份；无后端、无账号。
- 添加持仓：输入 6 位代码 → 数据源补名称、判定类型 → 手填 持仓成本价 + 份额/股数（可后改）。
- 添加现金账户：名称 + 所属人 + 平台 + 余额，随时改。
- 实时现价（API）自动计算 市值 与 浮动盈亏；接口不可用时沿用上次价并标记"行情未更新"。
- 记录点：每次改动打一个带日期的历史点（默认今天、可补记过去、可编辑/删除纠错）。
- 查看四页：总览（总资产 + 合计浮动盈亏 + 估值曲线）、资产（全部持仓/账户明细，行内更新 = 记录入口）、
  占比（按 人 / 平台 / 类型）、设置（标签管理 + 备份）。

## User Stories（自设计访谈收敛）

1. 添加基金/股票只输代码即可得到名称与类型，不用手敲名称。
2. 记录只需维护 持仓成本价 与 份额/股数 两个数；现价、市值、浮动盈亏全部自动算。
3. 现金账户随时改余额即完成记录，历史按改动时间点可看。
4. 任何时刻打开应用，看到的就是按最新行情计算的当前家庭总资产。
5. 份额/成本/余额变化后打点留痕；录错可编辑/删除该点；可补记过去日期。
6. 看到总资产随时间的变化曲线，以及按 人/平台/类型 的资产分布。
7. 数据可导出/导入 JSON 备份（单机无云）。
8. 断网或行情接口失败时不阻断查看：沿用最近现价并标记行情未更新。

## Implementation Decisions

- 领域核心为纯函数模块（参考原"快照库"的位置）：持仓/现金账户 CRUD、记录点、实时估值装配、
  估值曲线（记录点按当天价格估值）、占比聚合。UI 与持久化依赖此模块。
- 行情适配层单独封装（ADR 0003 的两个数据源 + 兜底 + 降级），UI 与领域核心不直连。
- 无交易流水：买卖通过"改份额 + 改成本价（用户自行摊薄）"表达；不做自动摊薄助手（v1.1 候选）。
- 场外基金现价 = 最近公布单位净值（白天为上一交易日值），不做盘中估值。
- 同代码多人/多平台各自成持仓；类型自动判定、允许手动纠正。
- 新数据结构独立存储键；旧 MVP 原型数据不迁移（结构不同，从头录入）。

## Out of Scope

- 港美股；交易流水与已实现收益追踪；与 App 数字自动对账；多用户/云同步。
- 定投/分红自动跟踪；买入摊薄助手；盘中估值；存款利率/到期日提醒。

## Testing Decisions

- 领域核心纯函数模块（CRUD、记录点、估值曲线、占比聚合、降级路径）用 Vitest 覆盖外部行为。
- 行情适配层通过注入 fetch 测试解析与失败降级。
- UI 层不单测。
